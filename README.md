# QUERY RUSH（query-rush）

UI Rush の骨格を SQL に移植した、4択で選ぶ認識ゲーム。

絞り込み前／後の小さなテーブルを見て、「どの条件でこうなったか」を固定4択チップで選ぶ。クエリを書く「生産」はさせない。認識と反応の速さで競い、速さはマルチタスクではなく「データを読む判断の速さ」から作る。

**遊ぶ**: https://tonbiattack.github.io/query-rush/

## モード

| モード | 内容 | 制限時間 |
| --- | --- | --- |
| Filter Rush | `WHERE` で行がどう絞られるか | 5秒 |
| Advanced | `AND` / `OR` / `IN` / `BETWEEN` / `LIKE` / NULL の三値論理 | 8秒 |
| Logic Rush | `CASE` / `COALESCE` / `NULLIF` / `EXISTS` の評価結果 | 8秒 |
| Aggregate Rush | `GROUP BY` / `HAVING` / 集計関数の結果 | 8秒 |
| Pipeline Rush | CTE（`WITH`）/ JOIN を段階的に追う | 15秒 |
| Master Rush | 全カテゴリ混合 | 8秒 |

制限時間は開始画面で 3／5／8／15 秒から選べます。スコアはモードと制限時間ごとに分けて記録します。

## 遊び方

1. 上段に「絞り込み前」と「絞り込み後」のテーブルが出る（最大8行。消える行は打ち消し線、残る行はハイライト）
2. 下段の固定4択から、その変化を起こした条件を選ぶ
3. 正誤表示中はタイマーが止まり、1行だけ解説が出る。正解でも不正解でも「次へ」で進む
4. 60秒タイムアタックで、スコア・正解数・最大ストリークを競う

### 操作

| 操作 | マウス／タッチ | キーボード |
| --- | --- | --- |
| 回答する | チップを押す | `1`〜`4` |
| 次へ進む | 「次へ」を押す | `Enter` |

## スコア

1問あたり最大300点。

- 基本 100点
- 速度ボーナス 0〜100点（残り時間に比例。「いま正解なら何点か」が画面に出る）
- ストリークボーナス 0〜100点（連続正解1つにつき+20）

不正解・時間切れは0点でストリークがリセットされる。ただしゲームは止まらない。

自己ベストと直近20件の履歴を `localStorage` に保存します（匿名・端末内のみ）。開始画面の「記録を消す」で削除できます。

## 起動

Node.js 22.16 以上（`node:sqlite` の `statement.columns()` を使うため）。追加の依存パッケージはありません。

### サーバーモード（ローカル開発）

```powershell
npm start
# → http://127.0.0.1:4173
```

起動時に固定データから一時SQLiteデータベースを生成し、読み取り専用で開きます。問題の生成と一意性検証をサーバー側で行います。

### スタティックモード（GitHub Pages と同じ構成）

```powershell
npm run build    # dist/ に静的サイトを出力
npm run preview  # → http://127.0.0.1:4174
```

ビルド時にSQLiteで問題を生成・検証し、`dist/questions.json` へ書き出します。ブラウザ内でゲームが完結するので、サーバーは不要です。

## 検証

```powershell
npm test                # ユニットテスト（SQLパーサー／問題生成／コアループ／HTTP）
npm run check:questions # 問題データの検証
```

`check:questions` は全データセットの候補を実際にSQLiteで実行し、各問題が次を満たすことを機械的に確かめます。

1. **一意性** — 4択のうち、正解でだけ目標の結果になる
2. **惜しさ** — 不正解は同じ列・似た列名・同じ種類の式から選ばれている（ランダムなダミーなし）
3. **行数** — 表示は最大8行に収まる
4. **変化** — 行が実際に減っている
5. **コスト** — 100ms / 100行を超えない

問題データを追加・変更したら必ず通してください。現在 **202問** が検証を通っています。

## 設計上の絶対条件

`docs/SPEC.md` の3点を守っています。実装で崩さないでください。

1. **問題は常時1問だけ** — 同時処理の忙しさを入れない
2. **4択スロットの位置は固定** — 探す時間ではなく選ぶ時間で勝負させる
3. **テーブルは最大8行・選択肢は4つ** — 難化は行数や選択肢ではなくデータ側の罠で行う

## セキュリティ

候補の条件式は文字列のままSQLへ流しません。`src/sql.js` で字句解析 → 構文解析 → AST検証 → ASTからの再生成を行い、許可したノード・関数・列だけを実行します。セミコロン・コメント・許可外の関数は実行前に拒否します。

## デプロイ

`main` へマージすると GitHub Actions が次を実行します。

1. `npm test` と `npm run check:questions` で検証
2. `npm run build` で静的サイトを生成
3. GitHub Pages へデプロイ

初回のみ、リポジトリ設定の Pages で Source を **GitHub Actions** にする必要があります。
