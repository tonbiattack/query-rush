# QUERY RUSH（query-rush）

UI Rush の骨格を SQL に移植した、4択で選ぶ認識ゲーム。

> ステータス: 仕様段階（コード未着手）。2026-11-17 に仕様 v2（認識ゲーム化）を採用。まず Issue #1 でMVP仕様を確定する。

## コンセプト

絞り込み前／後の小さなテーブルを見て、「どの `WHERE` でこうなったか」を固定4択チップで選ぶ。クエリを書く「生産」はさせない。認識と反応の速さで競い、速さはマルチタスクではなく「データを読む判断の速さ」から作る。

v1（2026-11-16）はチップを並べてクエリを組み立てる形式だったが、「勉強感・仕事感が強い」という指摘を受け、UI Rush / Type Rush の設計（見て選ぶ・間違いに寛容・解説は答えた後・スコアが残り時間と一緒に減る）を移植して v2 に書き換えた。経緯は [docs/SPEC.md](docs/SPEC.md) を参照。

## 遊び方（想定）

1. 絞り込み前 → 絞り込み後のテーブル（最大8行、変わった行がハイライト）が表示される。SQL文は出ない
2. 下段の固定4択チップから「どの `WHERE` でこうなった？」に1タップで答える（制限時間は1問5秒、3／5／8秒から設定可）
3. 正誤表示中はタイマーが止まり、1行だけ解説が出る。正解でも不正解でも次へ進む（ミスは速度ボーナス0とストリークリセットだけ）
4. 60秒タイムアタックで、スコア・正解数・最大ストリークを競う

## MVP範囲

- 60秒タイムアタック（正解数と合計スコア）が中心
- 問題は常時1問、4択スロットは固定、テーブル表示は最大8行
- スコアは基本100＋速度0〜100＋ストリーク0〜100（最大300／問）
- 苦手復習モードを含む。リバース（WHERE→結果テーブル）モードはMVP外でも可
- DBは SQLite（問題の生成・判定用）
- オンライン対戦・ランキングは対象外

## 技術スタック

- プラットフォーム: Web を第一候補（UI Rush / Type Rush と同じ土俵。Issue #1 で最終確定する）
- DB: SQLite
- UI: 固定4択チップUI（タップ／クリック、数字キー1〜4対応）
- 実装言語・フレームワーク: 未定（Issue #1 で確定する）
