# QUERY RUSH（query-rush）

寿司職人ゲーム × SQL の高速クエリ組み立てアクション。

画面をポチポチしながら高速でSQLを組む。キーボード入力はゼロで、句チップをタップ／クリックしてクエリを組み立てる。チップを置くたびにテーブルがその場で絞り込まれてハイライトされるライブプレビューが、気持ちよさの本体。速さはマルチタスクではなく「データを読む判断の速さ」から作る。

## 遊び方

1. 注文票が提示される（例「返品は除く。売上の高い順に3件。」）と、右上に完成形の結果プレビューが見える
2. 下段の句チップの棚からチップを押してクエリを組み立てる（押すたびに中段のテーブルへ即時反映）
3. 結果が注文と完全一致したら「提供する」で次の注文へ
4. 不一致のまま確定したり不正な組み合わせにしたりするとミスでコンボが切れる

60秒で何件捌けるかを競う。ミスせず繋ぐほどコンボ倍率が伸びるので、速さより「読み切る正確さ」の方が点になります。

### 操作

| 操作 | マウス／タッチ | キーボード |
| --- | --- | --- |
| チップを置く／外す | チップを押す | `1`〜`8` |
| 提供する | 「提供する」を押す | `Enter` |
| 配置をクリア | 「クリア」を押す | `Esc` |

## 起動

Node.js 22.16 以上（`node:sqlite` を使うため）。追加の依存パッケージはありません。

```powershell
npm start
# → http://127.0.0.1:4173
```

起動時に固定データから一時SQLiteデータベースを生成し、読み取り専用で開きます。ローカル専用の単一ゲームで、複数タブは同じ状態を共有します。クエリの取得上限は100行です。100ms超過は検出しますが、SQLiteの同期処理を実行途中で強制停止することはできません。

## 検証

```powershell
npm test              # ユニットテスト（エンジン／コアループ）
npm run check:orders  # 注文データの検証（解ける・一意・全チップ必須・罠が効く・衝突なし）
```

`check:orders` は棚のチップから作れる全192通りの配置を実際にSQLiteで実行し、各注文の完成形が「別解の無い一意な結果」であることを機械的に確かめます。注文を追加・変更したら必ず通してください。

## 構成

```
src/
  config.js   調整用パラメーター（【】付きの名前でSPECから参照）
  data.js     寿司屋の売上テーブル（罠を仕込んだシードデータ）
  chips.js    句チップの定義と棚の固定レイアウト
  orders.js   注文の定義（answer が完成形）
  engine.js   SQLite読み取り専用のクエリ実行基盤（差分・コスト超過つき）
  game.js     コアループ（判定／コンボ／タイマー／スコア）
  server.js   静的配信とJSON API
public/       3段構成のGUI（HTML / CSS / クライアントJS）
scripts/      注文検証・データ調査・スクリーンショット用
test/         ユニットテスト
```

## 設計上の絶対条件

`docs/SPEC.md` の3点を守っています。実装で崩さないでください。

1. **注文は常時1件だけ** — 同時処理の忙しさを入れない
2. **チップの配置は固定** — `SHELF_LAYOUT` をプレイ中にシャッフルしない
3. **同時表示チップは最大8枚** — 難化はチップ種類ではなくデータ側の罠で行う
